# The subject

## The problem
- A **treasure hunt** game platform: the player must find a treasure placed at an unknown position, along a path containing **reward** positions and **penalty** positions
- This exam has no official solution: the solution of this deck was written for the statement and **tested**
- Positions are numbers on a line from 0 to `N − 1`: the player starts at 0 and advances one cell at a time

| Element | Role |
|---|---|
| `Carte` | the map: a numpy plan and a dictionary `d` of the special cells |
| `Rules` | the rules of the game: failures allowed, moves allowed, counters |
| `Play` | inherits from `Rules`: the actions of the player |
| `Deco` | a decorator for `Repeat`: points for a won game, a new treasure |
| singleton | a code that allows only one `Carte` object |

## How the game works
- `d` holds the **special cells**: `d[i] = 10` is a **reward** cell, `d[i] = 0` is a **failure** cell, and the keys `"start"` and `"end"` hold the position of the player and the cell of the treasure
- A **reward** cell sends the player forward (`Jump`) or back (`Back`) depending on the side of the treasure
- A **failure** cell sends the player back to position 0 (`Check`)
- The game ends when the player reaches the treasure, or after too many jumps (`allow`)

# Question 1 · Carte

## Question 1: statement
- Define a class `Carte` with the attributes:
  - `N`: the size of the attribute `plan`, a numpy array of size `N` initialized to 1 (`N` is given by argument, 60)
  - an empty dictionary `d`. Add the position `"start"` with the value 0 and the position `"end"` with the position `Tr` (`Tr` is an attribute fixed through an argument)
- **`Affectation(R, F)`**: `R` is the number of **reward** positions and `F` the number of **failure** positions
  - it takes `R` random positions of `plan`, different from the treasure cell `Tr`, and sets them to the value 10. For each new position `i`, it checks that `i` is not already a key of the dictionary; the position is stored with `d[i] = 10`
  - it takes `F` random positions that send the player back to the start 0: the random generator is called `F` times; if the value is not already a key of the dictionary, it is added as `d[i] = 0`. Also `plan[i] = 0`
- **`Display`**: displays the dictionary `d`

## Question 1: solution
```python
import numpy as np

class Carte:
    def __init__(self, N=60, Tr=51):
        self.N = N
        self.Tr = Tr
        self.plan = np.ones(N)                         # the plan: N cells of 1
        self.d = {}
        self.d["start"] = 0                            # position of the player
        self.d["end"] = Tr                             # the treasure cell

    def Affectation(self, R, F):
        found = 0
        while found < R:                               # R different reward cells
            i = np.random.randint(1, self.N)
            if i != self.Tr and i not in self.d:       # not the treasure, not already taken
                self.d[i] = 10
                self.plan[i] = 10
                found += 1
        for k in range(F):                             # F draws for the failure cells
            i = np.random.randint(1, self.N)
            if i != self.Tr and i not in self.d:       # free cell only
                self.d[i] = 0
                self.plan[i] = 0

    def Display(self):
        print(self.d)
```
- `i not in self.d` tests the **keys** of the dictionary: the cells already taken
- The rewards **loop until `R` free cells** are found. The failures are only **drawn `F` times** (the subject says so): a draw on a taken cell is lost, so there can be fewer than `F` failure cells

## Question 1: remarks
- The positions are drawn from 1 to `N − 1`: the cell 0 is the **start** and does not get a reward or a failure
- The treasure cell `Tr` is also excluded from the failures, otherwise the treasure could disappear from the path
- `N = 60` and `Tr = 51` are default values: `Carte()` gives the map of the main program, and `Carte(100, 80)` another one
- Keys are of two kinds: the **strings** `"start"` and `"end"`, and the **integers** (the cells)

# Question 2 · Rules

## Question 2: statement
- Define a class `Rules` with an attribute `ob`, an object of the class `Carte`, and the attributes:
  - `allow`: the number of **failures allowed** · `nbr`: counts the failures (0 at the beginning) · `move`: the number of moves allowed to find the treasure · `compt`: a counter initialized to 0
  - `ob`, `allow` and `move` are given by arguments of `__init__`
- **`Check(pos)`**: receives the current position of the player, removes this position (a key) from the dictionary of `ob` and resets `"start"` to 0
- **`Stop`**: without argument, if `nbr` reaches the value of `allow`, it stops the program
- **`Reset`**: without argument, if `compt` equals `move`, the game restarts: `"start"` is reset to 0, and `nbr` and `compt` are reset to 0
- **`Display`**: calls the `Display` of `ob`, then displays `allow` and `move`

## Question 2: solution
```python
class Rules:
    def __init__(self, ob, allow, move):
        self.ob = ob                      # a Carte object
        self.allow = allow
        self.nbr = 0
        self.move = move
        self.compt = 0

    def Check(self, pos):
        del self.ob.d[pos]                # the cell disappears from the dictionary
        self.ob.d["start"] = 0            # back to the start

    def Stop(self):
        if self.nbr == self.allow:
            print("Stop: the number allowed is reached")
            return True
        return False

    def Reset(self):
        if self.compt == self.move:
            self.ob.d["start"] = 0
            self.nbr = 0
            self.compt = 0

    def Display(self):
        self.ob.Display()
        print("allow =", self.allow, " move =", self.move)
```
- `ob` is an object of **another class** stored as an attribute: `self.ob.d` is the dictionary of the map
- `del d[pos]` removes the key `pos` and its value

## Question 2: remarks
- A `break` can only be written **inside a loop**, not inside a function called from the loop. So `Stop` says that the limit is reached and returns `True`. The `break` of the game is the **`while` loop of `Repeat`**, which stops when `nbr` reaches `allow`
- After `Check`, the failure cell is **removed** from the dictionary: the player will not fall on it again, and he restarts from the position 0

# Question 3 · Play

## Question 3: statement
- Define a class `Play` that **inherits from `Rules`**: the actions of the player from the start position to the treasure cell `end`. Add an attribute `score` initialized to 0 and the functions:
  - **`Jump(a)`**: `a` is the new position of the player. It adds the **reward value** `d[a]` to the current position `d["start"]`. Then `nbr` is incremented and the inherited `Stop` is called
  - **`Back(a)`**: adds the **difference** `d[a] − d["end"]` to the current position `d["start"]`. Then `nbr` is incremented and `Stop` is called
  - **`Forward`**: no argument. The current position `x` is `d["start"]`
    - if `x` is a **reward** cell **lower** than `Tr`, `Jump` is called; if it is **higher**, `Back` is called
    - otherwise, if it is a **failure** cell, `compt` is incremented and `Check` is called
    - otherwise, the value of `"start"` is incremented
  - **`Repeat`**: `while nbr < allow`: call `Forward`; if `"start"` equals `"end"`, `break`; if `compt` equals `move`, call `Reset`. After the loop: `Display` and `Stop`

## Question 3: solution, Jump, Back
```python
class Play(Rules):
    def __init__(self, ob, allow, move):
        super().__init__(ob, allow, move)
        self.score = 0

    def Jump(self, a):
        self.ob.d["start"] += self.ob.d[a]                     # + the reward (10)
        self.nbr += 1
        self.Stop()

    def Back(self, a):
        self.ob.d["start"] += self.ob.d[a] - self.ob.d["end"]  # reward - treasure position
        self.nbr += 1
        self.Stop()
```
- `super().__init__(ob, allow, move)` runs the constructor of `Rules`; `Play` only adds `score`
- `Jump` makes the player **jump 10 cells** ahead (the reward value is added to the position). `Back` adds `10 − Tr`: a negative number, so the player goes **back**

## Question 3: solution, Forward
```python
    def Forward(self):
        x = self.ob.d["start"]                                  # the current position
        if x in self.ob.d and self.ob.d[x] == 10:               # a reward cell
            if x < self.ob.d["end"]:
                self.Jump(x)                                    # before the treasure
            else:
                self.Back(x)                                    # after the treasure
        elif x in self.ob.d and self.ob.d[x] == 0:              # a failure cell
            self.compt += 1
            self.Check(x)
        else:                                                   # a normal cell
            self.ob.d["start"] += 1
```
- `x in self.ob.d` tests that the position is a **key**: a special cell
- The value of the key tells the kind of cell: 10 for a reward, 0 for a failure
- A normal cell: the player simply moves **one cell forward**

## Question 3: solution, Repeat
```python
    def Repeat(self):
        while self.nbr < self.allow and self.ob.d["start"] < self.ob.N:
            self.Forward()
            if self.ob.d["start"] == self.ob.d["end"]:          # the treasure is found
                break
            if self.compt == self.move:
                self.Reset()
        self.Display()
        self.Stop()
```
- The loop is the game: each turn is one call of `Forward`
- `break` leaves the loop as soon as the player is on the treasure cell
- The condition `d["start"] < N` is **not in the subject**: a `Jump` can make the player pass over the treasure, and without this condition he would walk forever on the cells beyond the map

# Question 4 · The decorator

## Question 4: statement
- Create a decorator `Deco` for the method `Repeat`, to add points for the won games. The new function:
  1. starts by calling the **original function**
  2. adds **1000 points** to the score
  3. defines a **new position for the treasure** `Tr` and `d["end"]`, which must be **different from all the dictionary positions**
- **What is the modification to do on the original `Repeat` function to activate the decorator?**

## Question 4: solution, the decorator
```python
def Deco(fct):
    def nouveau(self):
        fct(self)                                    # 1. the original Repeat
        self.score += 1000                           # 2. the points
        while True:                                  # 3. a new treasure
            t = np.random.randint(1, self.ob.N)
            if t not in self.ob.d:                   # different from all the positions
                break
        self.ob.Tr = t
        self.ob.d["end"] = t
    return nouveau
```
- `nouveau(self)` replaces `Repeat`: it receives the object, runs the original method, then does the additional work
- `t not in self.ob.d` is `True` only when `t` is not the position of a reward or a failure cell
- The loop draws a number again until it is free: `break` leaves the loop

## Question 4: the answer
```python
class Play(Rules):
    ...
    @Deco                                    # the only change
    def Repeat(self):
        ...
```
- **We write `@Deco` just before the function `Repeat`**: it is the same as `Repeat = Deco(Repeat)` after it
- `Deco` must be **defined before** the class `Play`
- Each call of `Repeat()` plays a game and **then** gives 1000 points and moves the treasure for the next game
- As the subject says, the 1000 points are added after every call of `Repeat`

# Question 5 · One single Carte

## Question 5: statement
- To avoid several instantiations of the class `Carte`, propose a code that allows the creation of **only one object** of this class

## Question 5: solution
```python
class Carte:
    _instance = None                                     # the only object, when it exists

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:                        # first call: create the object
            cls._instance = super().__new__(cls)
        return cls._instance                             # all the calls: the same object

    def __init__(self, N=60, Tr=51):
        ...                                              # unchanged
```
- This is the **singleton** pattern: `__new__` **creates** the object and runs **before** `__init__`
- The first `Carte()` creates the object and keeps it in `_instance`; the following calls return it: `Carte() is Carte()` is `True`
- Another way (by inheritance, as in the 2023 and 2024 exams): write the class `Unique` with this `__new__` and the signature `class Carte(Unique)`
- Python runs `__init__` again at every `Carte(...)` call, on the same object: the map is reinitialized

# Question 6 · The main program

## Question 6: statement
- In the main program: create a `Carte` object (`N` = 60 and `Tr` = 51) and call `Affectation` with **5 rewards** and **3 failures**
- Create a `Play` object with `allow` and `move` set to 6
- Call `Repeat` to start a game

## Question 6: solution
```python
C = Carte(60, 51)
C.Affectation(5, 3)
C.Display()

P = Play(C, 6, 6)
P.Repeat()
print("score =", P.score, " new treasure =", C.Tr)
```
- `Play(C, 6, 6)` gives the map `C` to the rules: `P.ob` is `C`
- The random numbers change the run every time: the example below is one run
